# Design

Plotus uses warm paper tones, terracotta accents and a quiet sage palette to make a technical planning task feel approachable. Light and dark themes share the same layout and visual identity across iPhone and web.

The welcome screen pairs a miniature home illustration with “Make room for your next idea.” Google, Facebook and passkey actions sit below it. Projects keep names, locations and client details easy to scan.

The welcome illustration was newly drawn for Plotus. It is decorative and does not represent a checked or generated home design. The website favicon reuses the supplied Plotus mark. Desktop headers show the current section; account and appearance controls live in Settings. Detailed asset references are kept in the [source record](design-sources.json).

Plot setup follows the current **App design clean** flow: [mobile Boundary](https://www.figma.com/design/0AIbJahPpgu09bT3AqguPx?node-id=313-131949), [Direction](https://www.figma.com/design/0AIbJahPpgu09bT3AqguPx?node-id=313-133447), [Roads](https://www.figma.com/design/0AIbJahPpgu09bT3AqguPx?node-id=314-132220) and [desktop Boundary](https://www.figma.com/design/0AIbJahPpgu09bT3AqguPx?node-id=315-134015). The shared Kotlin canvas draws the measured geometry. Desktop uses plain Boundary, Direction and Roads tabs beside the canvas. The mobile main view shows Plot setup and Floor plan above the canvas. Selecting a section hides this stage strip. The mobile editor keeps the canvas above three section buttons and Upload plot image. Selecting a button reveals inline controls and compresses the header and canvas without opening a sheet. The selected section name appears beside the top back arrow, with Save on the right. The three buttons and upload hide while editing; Back restores the main canvas while keeping edits. Corner gestures preserve all side lengths and work only in the main view and Boundary; measured diagonals lock the angles. The compass fits the room inside the outline. The smaller keyboard layout keeps measurements and save actions reachable.

The floor-plan milestone follows [mobile Setbacks](https://www.figma.com/design/0AIbJahPpgu09bT3AqguPx?node-id=358-39125), [custom Requirements](https://www.figma.com/design/0AIbJahPpgu09bT3AqguPx?node-id=358-39930), [desktop Requirements](https://www.figma.com/design/0AIbJahPpgu09bT3AqguPx?node-id=358-61592), and the supplied room catalogue. Mobile controls remain inline under a fixed plot preview, following the approved interaction direction. Desktop keeps the canvas and inspector beside each other. The buildable outline comes from the connected engine; result drawings come only from accepted generations. Room icons are exact local exports of the supplied design.

This milestone includes saved setbacks, floor/home allocation, automatic or custom room programmes, bedroom features, shared spaces, durable generation, result drawings and explicit no-fit/error states. Room sizing stays automatic; unsupported catalogue entries are disabled. Per-room size preferences, free-form requirement interpretation, detailed comment editing, variation history and exports are deferred. No Figma example plan is used as a generated result.

The simplified floor-plan controls use two bottom options, Setbacks and Requirements. On mobile, selection opens inline controls, matching Plot setup. The section name and Save use the top bar; Back returns to the main canvas without discarding edits. The canvas toolbar owns measurement units. Setbacks place Auto/Custom on the label row, All sides beside its value, then per-edge choice and floors. Requirements flatten BHK, Vastu compliant and Auto/Custom; all room types share one catalogue and list, with no residence count, home cards, custom room-name field or separate shared-space section. Earlier residence data is retained in the saved archive when the single-residence brief is saved.
